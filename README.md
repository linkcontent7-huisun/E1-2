# E1-2 — 한국 가톨릭 성지순례 퀴즈 게임 (Python)

터미널에서 동작하는 퀴즈 게임입니다. 외부 라이브러리 없이 Python 표준 라이브러리만 사용했고, 퀴즈와 최고 점수는 `state.json`에 저장되어 프로그램을 종료해도 유지됩니다.

## 1) 프로젝트 개요

- 메뉴에서 번호를 골라 **퀴즈 풀기 / 추가 / 목록 / 점수 확인 / 삭제 / 게임 기록 / 종료**를 사용한다.
- `Quiz`(문제 한 개)와 `QuizGame`(게임 전체) 두 클래스로 역할을 나눴다.
- 잘못된 입력(문자, 범위 밖, 빈 입력, 공백), Ctrl+C·EOF, 데이터 파일 없음·손상을 모두 처리한다.
- 보너스 5종(랜덤 출제, 문제 수 선택, 힌트, 퀴즈 삭제, 점수 기록 히스토리)을 모두 구현했다.

## 2) 퀴즈 주제와 선정 이유

**주제: 한국 가톨릭 성지순례 상식** (기본 퀴즈 10문항)

- 제가 만들고 있는 **VisitHolyKorea**(한국 가톨릭 성지순례 웹앱)에서 그대로 재사용할 수 있는 콘텐츠를 만들고 싶었다. 순례 전에 배경 상식을 가볍게 확인하는 용도다.
- 사실 오류를 줄이려고 앱 저장소의 지식창고(`docs/40-knowledge`, 가톨릭굿뉴스·주교회의 자료 기반)에서 확인한 내용만 문항으로 썼다.
- 문항은 박해 사건(신해·신유·기해·병인), 김대건 신부, 시성(1984)·시복(2014)으로 구성했다.

## 3) 실행 방법

필요한 것: **Python 3.10 이상** (개발 환경: 3.14.2). 외부 설치는 없다.

```bash
git clone git@github.com:linkcontent7-huisun/E1-2.git
cd E1-2
python main.py
```

- 처음 실행하면 `state.json`이 없으므로 기본 퀴즈로 시작하고, 종료할 때 `state.json`을 만든다.
- 한글 Windows 콘솔에서도 이모지가 깨지지 않도록 `main.py`가 입출력을 UTF-8로 맞춘다.

## 4) 기능 목록

| 메뉴 | 기능 |
|---|---|
| 1. 퀴즈 풀기 | 풀 문제 수 선택 → 무작위 순서로 출제 → 정오답 안내 → 결과·최고 점수 갱신. 답 입력에서 `0`을 누르면 힌트(정답 0.5점 인정) |
| 2. 퀴즈 추가 | 문제, 선택지 4개, 정답 번호, 힌트(선택) 입력 후 `state.json`에 저장 |
| 3. 퀴즈 목록 | 등록된 퀴즈의 문제를 번호와 함께 표시 |
| 4. 점수 확인 | 최고 점수 표시. 아직 풀지 않았으면 안내 |
| 5. 퀴즈 삭제 | 번호 선택 → 확인 → 삭제 후 파일 반영 |
| 6. 게임 기록 | 모든 게임의 날짜·시간, 푼 문제 수, 힌트 횟수, 점수를 최근 순으로 표시 |
| 7. 종료 | 저장 후 종료 |

예외 처리: 앞뒤 공백 제거 / 숫자 변환 실패 / 범위 밖 / 빈 입력 → 안내 후 재입력, Ctrl+C·EOF → 저장 후 안전 종료, 파일 없음 → 기본 퀴즈, 파일 손상 → 안내 후 `state.json.bak`으로 옮기고 기본 퀴즈로 복구.

## 6) 데이터 파일 설명 (`state.json`)

- 위치: 프로젝트 루트 `state.json`, 인코딩 UTF-8.
- 게임을 하거나 퀴즈를 바꾸면 자동 저장되고, 종료할 때도 저장된다.

```json
{
  "quizzes": [
    {"question": "한국인 최초의 가톨릭 사제는?",
     "choices": ["정하상 바오로", "이승훈 베드로", "김대건 안드레아", "윤지충 바오로"],
     "answer": 3,
     "hint": "세례명은 안드레아이고, 1984년 103위 성인에 포함되었습니다."}
  ],
  "best_score": 100,
  "best_correct": 10,
  "best_total": 10,
  "history": [
    {"played_at": "2026-10-29 19:44:06", "total": 10, "correct": 10, "hints": 0, "score": 100}
  ]
}
```

| 키 | 설명 |
|---|---|
| `quizzes` | 퀴즈 목록. `answer`는 1~4번 번호, `hint`는 비어 있어도 된다 |
| `best_score` | 최고 점수(0~100). 아직 풀지 않았으면 `null` |
| `best_correct`, `best_total` | 최고 점수를 낸 판의 정답 수와 문제 수 |
| `history` | 모든 게임 기록. 없어도 읽을 수 있다(예전 파일 호환) |

점수 = (힌트 없이 맞힌 문제 + 힌트 쓰고 맞힌 문제 × 0.5) ÷ 푼 문제 수 × 100, 반올림.

## 9) 트러블슈팅

**1. 한글 콘솔에서 이모지 출력 시 `UnicodeEncodeError`**
- 문제: 메뉴 제목의 이모지를 출력하자 `'cp949' codec can't encode character '\U0001f3af'`로 종료.
- 원인 가설: 한글 Windows의 표준 출력 인코딩이 cp949라 이모지를 표현하지 못한다.
- 확인: 파이프로 실행할 때만 재현. 인코딩을 바꾸면 사라진다.
- 해결: `main.py`에서 `sys.stdout.reconfigure(encoding="utf-8")` (커밋 `Fix: cp949 콘솔에서 …`).

**2. 코드 생성 중 줄바꿈이 깨져 `SyntaxError`**
- 문제: 셸 here-doc으로 코드를 넣었더니 문자열 안의 `\n`이 실제 줄바꿈이 되어 `print(f"` 한 줄이 끊김.
- 원인 가설: 셸이 이스케이프 문자를 먼저 해석한다.
- 확인: 파일의 해당 줄이 `print(f"`에서 끊겨 있었다.
- 해결: 편집 도구로 `print()`와 `print(f"…")` 두 줄로 고침. 이후 문법 검사(`py_compile`)와 실행 확인을 통과한 경우에만 커밋.

**3. UTF-8 파이프 입력의 한글이 저장 단계에서 `UnicodeEncodeError`**
- 문제: 한글 퀴즈를 추가한 뒤 저장하는 순간 `surrogates not allowed`로 종료.
- 원인 가설: 입력 인코딩이 cp949로 해석되어 잘못된 글자(surrogate)가 생기고, UTF-8 저장에서 실패한다.
- 확인: 실행 로그 작성 중 재현. `stdin`을 UTF-8로 바꾸자 사라졌고, 저장된 `state.json`에서 한글이 정상 확인됨.
- 해결: `main.py`에서 입력도 UTF-8로 맞추고, 저장 실패는 `OSError`뿐 아니라 `ValueError`도 잡도록 수정 (브랜치 `fix/utf8-stdin`).
